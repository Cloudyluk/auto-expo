# 采购路径决策升级设计

## 目标

在既有“采购路径 → 供应链总成 → 相关展会”中，帮助采购人员判断是否值得去某场展会，并把参展行为导向供应商开发、技术选型、降本、准入或售后供应链的下一步动作。

不新增采购入口，不改动销售路径的导航结构。

## 用户输入

用户先从现有供应链总成进入，再选择一项或多项采购任务：

- 新供应商开发 / 第二供应商
- 技术选型与方案比较
- 降本、材料替代与本地化
- 供应商质量、认证与产能评估
- 售后、再制造与逆向供应链

后续版本可加项目阶段和目标市场；第一版不要求用户填写额外表单。

## 决策输出

每个总成页显示：

1. 采购任务说明，说明当前任务的决策目标。
2. 展会按可解释规则排序：首选、建议去、仅补充、不建议投入。
3. 每场展会显示四项结论：
   - 为什么去：展会主题与总成、采购任务的匹配依据。
   - 现场要拿到什么：候选供应商、样品/报价、技术资料、认证/产能或验证资源。
   - 不去的条件：何种场景下不应使用该展会作为主寻源场。
   - 替代选择与行动：应改选垂直展、材料展、测试展或采用线上筛选/预约拜访。

## 供应链任务映射

| 供应链位置 | 优先任务 | 首选展会价值 |
| --- | --- | --- |
| 原材料与材料工艺 | 替代料、降本、性能验证 | 材料、加工工艺、轻量化和认证资源 |
| 零部件与系统 | 新供应商、第二供应商、平台选型 | Tier 1/2、工艺能力、产能和质量体系 |
| 三电 | 技术路线、验证、供应安全 | 电池、电驱、功率器件、验证与认证资源 |
| 智能化与软件 | 技术选型、联合开发、合规 | 芯片、传感器、域控、软件和测试资源 |
| 制造装备 | 扩产、效率、工艺升级 | 设备、自动化、模具、检测与集成商 |
| 质量、认证与法规 | 准入、验证、供应商审核 | 实验室、认证机构、测试设备和法规服务 |
| 售后、再制造与物流 | 渠道、逆向物流、维修与回收 | 服务网络、配件流通、回收和仓储伙伴 |

## 排序规则

优先级由以下字段决定，所有结论必须能对应到展示数据：

```text
总成匹配度 + 采购任务匹配度 + 项目阶段匹配度
+ 目标市场匹配度 + 数据可信度
```

第一版使用现有总成分类、展会分类、星级、官方链接和状态；任务、项目阶段、市场和可信度字段缺失时不虚构事实，展示为“待核验”或使用保守建议。

## 数据与组件边界

- `BUYER_PATHS`：继续定义供应链总成和基础采购任务。
- `PROCUREMENT_TASKS`：定义五类采购任务及其说明、现场产出、替代动作。
- `PROCUREMENT_RULES`：定义“总成 × 任务”对展会分类的优先级和不建议条件。
- `rankProcurementEvents()`：按当前任务排序并返回解释标签。
- `procurementDecisionPanel()`：渲染总成级任务说明和行动建议。
- `procurementEventDecision()`：渲染每场展会的理由、收获、跳过条件与替代选择。

销售路径不消费这些采购规则；销售页面仅保留跳转查看采购需求的现有能力。

## 可信度要求

不得凭空声称某场展会有特定数量的目标供应商、某类采购负责人必然出席或一定产生项目机会。此类结论必须有官方展商目录、往届报告或主办方资料；没有证据时使用“主题匹配”“建议核验展商名单”等表达。

## 验证

- 每个采购总成可选择至少一种采购任务。
- 切换任务后，列表的优先级、理由和行动建议随之变化。
- 每张采购展会卡都包含为什么去、现场收获、不去条件和替代动作。
- 无官方来源或日期待核验的展会不被表述为确定性推荐。
- 既有月度、地图、分类、国内、海外和销售路径不受影响。
